# Exploration: escrow-claimable-ttl-evaluator-guard (issue #95)

## Current State
- `contracts/contracts/escrow/src/lib.rs`: `extend_ttl(e, job_id)` (~L753) calls `extend_instance`, then bumps `DataKey::Job(job_id)` only if it exists.
- `DataKey::Claimable(recipient, token)` (L116) is bumped only in `pay_or_defer` (~L889). `withdraw` (L662) and `claimable` (L682) read it without bumping. An entry untouched for ~60 days (`TTL_BUMP` = 1,036,800 ledgers) is archived.
- `extend_persistent` (L932) wraps `extend_ttl(key, TTL_THRESHOLD, TTL_BUMP)`. Soroban `extend_ttl` on a missing key panics, hence the `has` guard.
- `create_job` (L410-429) validates: hook, budget, description length, expiry, token allow-list, `caller == provider` -> `ClientIsProvider` (L426), then `verify_provider`. No evaluator check exists.
- `EscrowError` is `#[repr(u32)]`: 1-11 from ERC-8183, 100+ puls3 additions, last used `NothingToWithdraw = 116`. Codes are ABI (append-only). Next free: 117.
- Tests live in `src/test.rs`: `setup()` / `setup_mock(fee)` -> `Ctx`; `client_cannot_be_the_provider` (L661) is the template; `third_party_evaluator_is_stored` (L499) is the regression check; `a_claimable_entry_is_bumped_and_kept_alive` (L2582) shows how to read Claimable TTL. An exported-functions allowlist test (~L2200-2258) must gain the new fn name.
- Snapshots: `contracts/contracts/escrow/test_snapshots/test/<test>.1.json`, generated by `cargo test`; never hand-edit.
- `contracts/README.md` has no escrow API/error section; the acceptance criterion needs a minimal Escrow section.
- ADR-0005 D4: client is the default evaluator; third-party evaluators allowed. The guard is anti-self-dealing, consistent with `ClientIsProvider`.
- Precedent: archived `2026-10-04-enforce-max-fee-bps`. Parent spec: `openspec/changes/agent-escrow-payment/specs/agent-escrow-lifecycle/spec.md` (R11 L441, R14 L459).

## Approaches (Claimable TTL)
1. **New `extend_claimable_ttl(recipient, token)`** - permissionless, bumps instance + key if present. Explicit, keyed correctly, no change to existing ABI/snapshots. Effort: Low. **Recommended.**
2. **Extend `extend_ttl`** - Soroban cannot enumerate keys; only `(job.provider, job.token)` / treasury derivable, so coverage is partial and silent; changes an existing function's footprint. Effort: Medium.
3. Bump inside `claimable()`/`withdraw` - rejected (views must not write; `withdraw` removes the key).

## Recommendation
- Add `pub fn extend_claimable_ttl(e, recipient, token)`: no auth, `extend_instance`, then `extend_persistent` only if `has(Claimable(recipient, token))`; no event, no return, never reverts on missing key.
- Add `EvaluatorIsProvider = 117`; guard directly after the `ClientIsProvider` check, before `verify_provider`.
- Strict TDD tests: evaluator==provider rejected (no job stored, count unchanged, no event); evaluator==client and third-party still accepted; claimable TTL restored to `TTL_BUMP` after decay and still withdrawable; unknown claimable only bumps instance; allowlist updated.

## Risks
- New public fn + error change the ABI; deployed instance lacks them until redeploy (#84, out of scope).
- Code 117 may collide with other open branches; confirm free before merge.
- Snapshot churn: verify only new files appear.
- Downstream error-code consumers (Serverpod/Flutter mapping, #77) may need code 117 (unchecked).
- evaluator==provider self-service is excluded by design, as the issue mandates.

## Ready for Proposal
Yes.
