# Target MVP C4 diagrams

These diagrams describe the **target MVP architecture**, not the current implementation. Today the repository contains a Flutter demo backed by mock/asset data and a mostly scaffolded Serverpod server; the domain package, Soroban contracts, live wallet/payment flow, catalog indexing, and agent runtime shown below are still planned. The decisions behind the target are in [ADR-0001](../adr/0001-system-architecture.md). Diagrams use Mermaid flowcharts (not the experimental Mermaid C4 syntax), so they render on GitHub.

## Level 1: System context

Who uses puls3, and which outside systems it depends on.

```mermaid
flowchart TB
  builder["<b>Agent builder</b><br/>[Person]<br/>Creates, tests, and deploys agents,<br/>and earns USDC when they are hired"]
  consumer["<b>Agent consumer</b><br/>[Person or agent]<br/>Finds agents, hires them,<br/>pays per task, and rates the result"]

  puls3["<b>puls3</b><br/>[Software system]<br/>Agent Studio + Marketplace:<br/>create, find, hire, and pay AI agents"]

  wallet["<b>Stellar wallet</b><br/>[External system]<br/>Holds the user's keys and<br/>signs the user's transactions"]
  stellar["<b>Stellar network</b><br/>[External system]<br/>Soroban contracts, USDC,<br/>and settlement (testnet for the MVP)"]
  llm["<b>LLM provider</b><br/>[External system]<br/>Runs the model behind each agent"]
  x402["<b>x402 facilitator</b><br/>[External system]<br/>Verifies and settles x402 payments.<br/>Used only if ADR-0003 picks x402"]

  builder -->|"Defines and deploys agents"| puls3
  consumer -->|"Searches, hires, pays, rates"| puls3
  builder -->|"Signs agent registration"| wallet
  consumer -->|"Signs payments and feedback"| wallet
  wallet -->|"Submits signed transactions"| stellar
  puls3 -->|"Reads registries, verifies payments,<br/>manages agent wallets"| stellar
  puls3 -->|"Sends agent tasks"| llm
  puls3 -.->|"Optional: payment verification"| x402
  x402 -.->|"Settles payments"| stellar
```

## Level 2: Containers

What runs inside puls3, and how the containers talk to each other and to the chain.

```mermaid
flowchart TB
  user["<b>Builder / consumer</b><br/>[Person]"]
  wallet["<b>Stellar wallet</b><br/>[External]<br/>Signs the user's transactions"]

  subgraph puls3 ["puls3"]
    app["<b>Flutter app</b><br/>[Flutter web, puls3_flutter]<br/>Studio and Marketplace UI.<br/>Builds the user's transactions<br/>and sends them to the wallet to sign"]
    server["<b>Serverpod server</b><br/>[Dart, Serverpod 3, puls3_server]<br/>Endpoints, catalog indexing,<br/>on-chain payment verification,<br/>agent runtime, agent wallets"]
    domain["<b>Domain</b><br/>[Pure Dart package, puls3_domain]<br/>Entities, business rules, ports.<br/>No framework or chain imports"]
    db[("<b>Database</b><br/>[PostgreSQL]<br/>Agents, drafts, hires,<br/>indexed on-chain data")]
    cache[("<b>Cache</b><br/>[Redis]<br/>Serverpod caching and<br/>session data")]
  end

  subgraph chain ["Stellar network (testnet)"]
    rpc["<b>Stellar RPC</b><br/>[JSON-RPC over HTTPS]<br/>Reads ledger state and events,<br/>simulates and submits transactions"]
    identity["<b>Identity Registry</b><br/>[Soroban contract, Rust]<br/>Agent owner, payment address,<br/>metadata URI (issue 13)"]
    reputation["<b>Reputation Registry</b><br/>[Soroban contract, Rust]<br/>Feedback from paying consumers (issue 14)"]
    usdc["<b>USDC</b><br/>[Stellar asset + its SAC]<br/>The currency agents are paid in"]
  end

  llm["<b>LLM provider</b><br/>[External HTTP API]<br/>Runs agent tasks"]

  user -->|"Uses, HTTPS"| app
  app -->|"Calls endpoints<br/>[Serverpod client, HTTPS]"| server
  app -->|"Asks to sign"| wallet
  wallet -->|"Submits register, pay, feedback"| rpc
  server -->|"Uses"| domain
  app -->|"Uses"| domain
  server -->|"Reads and writes<br/>[Serverpod ORM]"| db
  server -->|"Caches"| cache
  server -->|"getTransaction, getEvents,<br/>getLedgerEntries (xdrFormat json),<br/>submits agent-wallet txs"| rpc
  server -->|"Runs tasks, HTTPS"| llm
  rpc --- identity
  rpc --- reputation
  rpc --- usdc
```

## Reading guide

- **Solid arrow:** a required call or data flow in the target MVP. It does not imply that the flow exists in the current repository. **Dashed arrow:** optional, depends on a pending decision.
- The **domain** is a library, not a process: both the app and the server compile it in. It never calls anything; the arrows point *to* it (dependency rule in ADR-0001 §1).
- The **wallet** signs every transaction that spends the user's funds or commits to the user's identity. The server signs only for agent wallets (ADR-0001 §4).
