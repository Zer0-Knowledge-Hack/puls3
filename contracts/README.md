# puls3 contracts

Soroban smart contracts for puls3, as one Cargo workspace. The registries are defined in [ADR-0002](../docs/adr/0002-agent-registry-on-soroban.md).

```text
contracts/
├── Cargo.toml              # workspace: shared soroban-sdk version and release profile
└── contracts/
    └── placeholder/        # sample contract so CI has something to build and test (#29)
        ├── Cargo.toml
        └── src/
            ├── lib.rs
            └── test.rs
```

Each contract is a crate under `contracts/<name>/` that takes `soroban-sdk` from the workspace. The Identity Registry (#13) goes in `contracts/identity-registry/` and the Reputation Registry (#14) in `contracts/reputation-registry/`.

## Versions

| What | Version | How it was checked |
|---|---|---|
| Testnet protocol | **28** | Stellar RPC `getVersionInfo` on `https://soroban-testnet.stellar.org`, 2026-09-24 |
| `soroban-sdk` | **28.0.0** (`"28"` in `Cargo.toml`) | Major matches the testnet protocol. Pinned in `Cargo.lock` |

Check the testnet protocol yourself:

```bash
curl -s -X POST https://soroban-testnet.stellar.org \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"getVersionInfo"}'
# look for "protocolVersion": 28
```

When testnet upgrades to a new protocol, bump the `soroban-sdk` major in an issue of its own.

## Prerequisites

| Tool | Version | Install |
|---|---|---|
| Rust (stable) | **1.98.1** or newer | https://rustup.rs |
| `wasm32v1-none` target | — | `rustup target add wasm32v1-none` |
| Stellar CLI | **28.0.0** (at least **25.2.0**: `soroban-sdk` 28 refuses to build with older versions) | https://developers.stellar.org/docs/tools/cli/install-cli · Windows: `winget install --id Stellar.StellarCLI` |

Check your setup:

```bash
rustc --version            # rustc 1.98.1 or newer
rustup target list --installed | grep wasm32v1-none
stellar --version          # stellar 28.0.0
```

## Commands

Run everything from this folder (`contracts/`).

| Task | Command |
|---|---|
| Build every contract to WASM | `stellar contract build` |
| Test | `cargo test` |
| Check formatting | `cargo fmt --all -- --check` (fix with `cargo fmt --all`) |
| Lint | `cargo clippy --all-targets -- -D warnings` |

`stellar contract build` writes one `.wasm` per contract to `target/wasm32v1-none/release/`, e.g. `target/wasm32v1-none/release/placeholder.wasm`. Build a single contract with `stellar contract build --package <name>`.

Run all four before opening a PR. CI (#29) runs the same commands.

## Release profile

`Cargo.toml` uses the release profile generated by `stellar contract init`: `opt-level = "z"`, `overflow-checks = true`, `panic = "abort"`, `lto = true`, `codegen-units = 1`, `strip = "symbols"`, `debug = 0`, `debug-assertions = false`. Do not remove `overflow-checks`: our contracts handle amounts, and an overflow must abort the transaction instead of wrapping. A `release-with-logs` profile is also available for debugging ([logging docs](https://developers.stellar.org/docs/build/smart-contracts/example-contracts/logging#cargotoml-profile)).

## Adding a contract

```bash
stellar contract init . --name <name>   # from this folder; existing files are not overwritten
```

Then build, test, format, and lint as above.
